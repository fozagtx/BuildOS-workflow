# Problem Workflow

Use for full discovery runs.

## Step 0: Intake

Record:

- Original framing
- Implied solution, if any
- Who the user named as the user
- Decision this informs
- Expected output

## Step 1: Restate from the worker

Name the person closest to the pain. Rewrite the problem as a job they are already trying to finish today.

Ask: who does the real work, with their hands on the mess, at the moment the cost shows up?

If the user named a buyer, owner, SME, "the market", or a demographic, stop and use the three doer questions in [workaround-map.md](workaround-map.md). See E01 / E09 / E24 in [edge-cases.md](edge-cases.md).

## Step 2: Current workarounds

List what they actually do today. See [workaround-map.md](workaround-map.md).

If you cannot name a workaround, emit the **suspect report** from [edge-cases.md](edge-cases.md) and stop. Do not invent workarounds. Do not sharpen. A good problem already has messy workarounds. If nobody is doing the work, there is no felt pain.

## Step 3: Score the signals

Score fragmentation, incentive misalignment, incumbent neglect, and cost bearer. See [signal-scores.md](signal-scores.md).

Low scores across the board usually mean an obvious, feel-safe framing.

## Step 4: Reject obvious framings

Name the feel-safe versions and say why they fail. See [framing-reject.md](framing-reject.md). Do this even if the user is attached to them.

## Step 5: Sharpen

Output 2-3 ranked one-sentence problem statements using the exact report headings in [sharpen.md](sharpen.md). Skipping the template is a failure. See E27 / E28.

Rank by signal strength. If a sentence is missing worker, workaround, or structural gap, rewrite it (E20).

## Stop rule

Stop when you can name the worker, the workaround, and the structural reason the symptom stays unfixed. Do not keep going until a product idea appears.

If the user asks what to build before this report exists, answer with the report (E06). After it exists, stay inside sharpened #1 (E07, E08, E30).
